# PR 생성

프로젝트의 `.github/PULL_REQUEST_TEMPLATE.md` 양식에 맞춰 PR을 생성한다.

## 워크플로우

### 1. 변경사항 분석

PR 생성 전에 다음을 확인한다:

- 현재 브랜치의 base 브랜치 확인 (원격 default 브랜치를 조회하여 결정한다)
- base 브랜치와의 diff
- 커밋 히스토리
- 변경된 파일 목록

### 2. PR 템플릿 확인

프로젝트 루트에서 `.github/PULL_REQUEST_TEMPLATE.md`를 찾는다.

**템플릿이 있는 경우**: 3단계로 진행한다.

**템플릿이 없는 경우**: 아래 기본 양식을 사용한다.

```markdown
## 변경 내용

<!-- 무엇을 왜 변경했는지 -->

## 관련 이슈

<!-- 관련 이슈 번호 (없으면 삭제) -->
```

### 3. PR 템플릿 채우기

템플릿의 각 항목을 변경사항에 맞게 채운다.

- 변경 내용은 커밋 메시지와 diff를 기반으로 무엇을 왜 변경했는지 요약한다
- 체크박스 항목은 실제로 검증한 뒤 결과에 따라 처리한다:
  - 충족: `- [x]` 체크
  - 미충족: `- [ ]` 체크하지 않고, 아래에 미충족 사유를 기재한다 (예: `- [ ] README.md 스킬 목록 업데이트 — ⚠️ 미반영`)
  - 해당 없음: 항목 자체를 제거한다

### 4. PR 생성

- PR 제목: 70자 이내, 변경 내용을 요약
- PR 본문: 템플릿에 맞춰 채운 내용을 사용
- base 브랜치: 1단계에서 확인한 브랜치
