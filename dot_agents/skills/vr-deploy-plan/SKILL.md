# 배포 플랜 작성

Notion 배포 트래커 DB에 배포 플랜 페이지를 생성하고 사용자와 공동 작성한다.

- **배포 트래커 DB**: `https://www.notion.so/20bcf5759dc080edac25d6220aafdefb`
- **JIRA**: `https://vroong-jira.atlassian.net`
- DB 속성, 옵션, 템플릿 구조는 모두 런타임에 Notion에서 동적 조회한다

## 워크플로우

### Phase 1~4: 정보 수집 (병렬)

네 단계는 서로 의존성이 없으므로 병렬 실행한다.

#### Phase 1: Diff 탐색

1. 최근 태그 목록을 조회한다
2. SNAPSHOT, RC 등 비상용 태그를 제외하고 상용 배포 태그만 필터링한다
3. 필터링된 태그 목록을 사용자에게 보여주고 배포 태그를 확인한다
4. 롤백 버전을 결정한다: 배포 태그 바로 이전 상용 태그를 자동 선택하여 사용자에게 확인한다
5. 상용 태그 간 변경 내역을 수집한다 (롤백 버전 ~ 배포 태그):
   - git log, git diff --stat
   - 커밋 메시지에서 JIRA 티켓 번호를 추출하여 JIRA 링크를 생성한다 (예: `https://vroong-jira.atlassian.net/browse/ITSMCHG-30747`)
   - Merge commit에서 PR 번호를 추출하여 PR 제목/링크를 수집한다
   - 추출된 티켓/PR 링크는 초안 작성 시 관련 섹션에 포함한다

**태그가 없는 경우(최초 배포)**: 사용자에게 비교 기준을 확인한다.

#### Phase 2: 템플릿 탐색

1. Notion 배포 트래커 DB에서 템플릿 목록을 조회한다
2. 가장 최신 템플릿을 사용자에게 제안하여 확인한다
3. 확정된 템플릿을 fetch하여 섹션 구조를 파악한다

#### Phase 3: 기존 배포 플랜 탐색

1. Notion 배포 트래커 DB에서 최근 완료된 배포 플랜 3~5건을 조회한다
2. 문서 스타일, 작성 패턴, 톤을 파악한다
3. 초안 작성 시 일관성 유지를 위한 레퍼런스로 활용한다

**기존 배포 플랜이 없는 경우**: 템플릿 구조만으로 진행한다.

#### Phase 4: 사용자 식별

1. Notion API로 현재 사용자의 프로필(이름, ID)을 조회한다
2. 조회한 사용자 정보는 Phase 7(페이지 생성)에서 작성자 설정에 활용한다

**사용자 프로필 조회에 실패한 경우**: 사용자에게 이름을 직접 확인한다.

### Phase 5: 분석 및 구체화

Phase 1~4의 결과를 합류하여:

1. **섹션 분류**: 템플릿 섹션을 diff 데이터와 대조하여 "자동 초안 가능" / "사용자 논의 필요"로 분류한다
2. **정보 파악**: 자동으로 채울 수 없는 항목을 사용자에게 질문하여 수집한다
   - 배포를 실제 수행하는 담당자(배포 오퍼레이터)는 누구인가?
   - 이번 배포로 영향받는 서비스/모듈은 무엇인가?
   - 배포 시작 시간과 각 단계별 소요 시간은 얼마인가?
   - 예상 위험 요소는 무엇인가?
   - QA 상태와 관련 문서 링크는?
   - 배포 순서는 어떻게 되는가?
   - 위 항목은 기본 질문이다. 섹션 분류 결과 자동으로 채울 수 없는 항목이 추가로 발견되면, 해당 섹션에 맞는 질문을 추가로 생성하여 사용자에게 확인한다

### Phase 6: 초안 작성 + 보완

- "자동 초안 가능"으로 분류된 섹션은 diff 데이터 + 기존 문서 스타일을 참조하여 초안을 작성한다
- "사용자 논의 필요"로 분류된 섹션은 사용자와 하나씩 확인/보완한다
- 각 섹션 확인 후 최종 확정한다

### Phase 7: 페이지 생성

1. Notion 배포 트래커 DB에 페이지를 생성한다 (확정된 템플릿 적용)
2. DB 속성을 설정한다 (동적으로 조회한 옵션 기반, 사용자 확인 후)
3. Phase 4에서 조회한 사용자 정보로 작성자를 설정한다
4. 확정된 본문 내용을 채운다
5. 생성된 페이지 URL을 사용자에게 공유한다

## 주의사항

- 페이지 제목 형식: 기존 배포 플랜의 패턴을 따른다
- 진행 상태는 "작성중"으로 시작한다
- 배포일은 사용자에게 확인 후 설정한다 (임의로 넣지 않음)
- 롤백 버전은 이전 상용 태그 기반으로 제안하고, 사용자 확인을 필수로 한다
- DB 속성은 후보를 제안하여 사용자가 확정한다
- 매칭되는 옵션이 없으면 비워두고 사용자에게 확인한다
- 본문 레이아웃은 단일 컬럼으로 작성한다
- TOC(목차)가 포함된 템플릿의 경우, TOC를 좌/우 컬럼 레이아웃으로 배치하지 않고 페이지 상단에 배치한다 (Notion MCP가 full width column을 지원하지 않음)
- 배포 시간은 사용자에게 시작 시간과 단계별 소요 시간을 확인한 뒤, 누적 계산하여 기입한다 (임의로 채우지 않음)
- Notion 접근 실패 시 사용자에게 알리고 대안을 제시한다
