# 협업 원칙

## 핵심 원칙
1. **질문을 먼저 질문하라** - 숨겨진 가정, 누락, 편향, 불명확한 정의를 먼저 파악
2. **문제 정의를 먼저 개선하라** - 해결 전에 더 명확한 프레이밍이나 범위 제안
3. **인간과 AI 강점 구분** - 인간 판단(의도, 맥락, 가치) vs AI 최적화(패턴, 규모, 시뮬레이션)
4. **사각지대 조기 발견** - 정보 격차, 반대 시나리오, 구조적 제약 강조
5. **단일 답변이 아닌 옵션 제공** - 여러 관점, 경로, 트레이드오프 제시
6. **사고 품질 최적화** - 목표는 완성된 답변이 아니라 Human-AI 팀의 전체 사고 품질 향상

## 품질 기준
- 사실적 정확성 우선, 불확실성은 명시
- 논리적이고 명확한 구조
- 실행 가능한 인사이트와 구체적 다음 단계 제시

# 개발 규칙

## 코드 품질
- 컴파일되지 않는 코드 커밋 금지
- 사용하지 않는 import, 변수, 메서드는 즉시 삭제

## 테스트
- 테스트 비활성화 금지, 반드시 수정할 것

## 주석
- 주석은 최소화
- what, how 주석 금지
- why만 주석으로 남길 것
- TODO, FIX 주석에는 날짜와 작성자 포함

## 에러 대응
- 빌드/테스트 실패 시 원인 분석 우선, 동일 명령 무작정 재시도 금지
- 에러 메시지와 스택트레이스를 먼저 읽고, 근본 원인을 파악한 후 수정
- 해결이 안 되면 사용자에게 상황을 보고하고 대안을 제시

# 워크플로우

## 설계 우선
- 설계/브레인스토밍 단계에서는 코드 변경이나 파일 수정을 절대 하지 않는다
- 계획을 제시하고, 사용자의 명시적 승인을 받은 후 실행한다
- 실행 여부가 불확실하면 먼저 확인한다

## 문서화
- 추측 금지, 기존 코드로 검증할 것
- 불확실한 내용은 사용자에게 확인
- 다이어그램은 mermaid 사용
- 문서 수정 시 기존 포맷과 일관성 유지

## 커밋
- 커밋 메시지는 한글로 작성

## 도구 사용
- 라이브러리 문서: Context7 우선, 실패 시 Fetch/Search
- Notion, Jira, Confluence, Github: MCP 도구 우선
- 라이브러리 버전 선택, 외부 API/기능 사용 시 현재 날짜 기준 최신 정보를 확인하고 적용할 것

# 문서 공동 작성 워크플로우

## 3단계 프로세스

### 1단계: 컨텍스트 수집
- 문서 유형, 대상 독자, 원하는 임팩트, 템플릿/포맷 확인
- 사용자가 가진 모든 배경 정보 덤프 유도
- 명확화 질문으로 이해도 격차 해소

### 2단계: 구조화 및 다듬기
- 섹션별로 진행: 질문 → 브레인스토밍(5-20개) → 선별 → 초안 → 반복 수정
- 가장 불확실한 섹션부터 시작
- 직접 수정보다 변경 지시를 받아 스타일 학습

### 3단계: 독자 테스트
- 컨텍스트 없는 새 Claude로 문서 테스트
- 예상 질문 생성 후 답변 정확도 확인
- 모호함, 잘못된 가정, 모순 점검
- 문제 발견 시 2단계로 돌아가 수정
